# 基于状态机的文档语义切片实施方案

> 面向项目：`rag-xmut-main`（Spring Boot + Java 21 + Spring AI + Milvus）
> 背景：当前 `RagKnowledgeService.chunk()` 采用**固定 500 字 + 120 重叠**的硬切分，导致语义被拦腰截断（例：新手册 `当事人将承担相` 一句被切成两段），检索命中与回答质量下降。
> 目标：依据用户提供的三张状态机设计图，将切片改造为**结构感知的语义切块**，输出语义完整、层级可定位、对 `jmu新生手册.txt` 友好的知识块。
> 前置说明：本文仅作方案，**不涉及任何代码改动**。用户确认后（点击批准）再进入编码实施。
> 日期：2026-09-11

## 一、三张状态机图的设计语义

| 图 | 状态机 | 解决的问题 | 输入→输出 |
| --- | --- | --- | --- |
| 图1 | **标题层级状态机**（切割主体） | 让切块贴合标题结构，"一整个语义块"完整入库 | 行流 → 语义块 `List<String>` |
| 图2 | **曲调行过滤状态机**（字符级判定） | 校歌简谱行（纯数字+点+横线+竖线）污染文本，须剔除 | 行 → 保留/丢弃 |
| 图3 | **表格识别状态机**（NORMAL↔IN_TABLE） | 报表/收费表必须整体保存，不能被标题机或长度机撕碎 | 行流 → 原子表格块 |

三者组合为**一条双向流水线**：先 `clean()`（图2 + 图3，行级清洗、抽出表格块），再 `chunk()`（图1，对清洗后的行流按标题语义切块）。

```
importDocument(filePath)
        │  Files.readString
        ▼
   clean(text)  ──► 过滤曲调行(图2) + 识别表格块(图3)
        │          输出：干净的"正文行流" + 一批"原子表格块"
        ▼
   chunk(cleanedText)  ──► 标题状态机(图1) 逐行累积
        │                 遇同级/上级标题 flush；超长块按段落兜底
        ▼
   List<String> chunks ──► 嵌入 Embedding ──► 写 Milvus
```

## 二、图3 —— 表格识别状态机（`clean` 的第 1 步）

### 2.1 状态
`NORMAL`（普通文本） / `IN_TABLE`（表格内）。

### 2.2 关键 token
- **表格分隔行（唯一进入信号）**：Markdown 管道表格切分表头与表体的 `|---|` 行。
  ```regex
  ^\s*\|?\s*:?-+:?\s*(\|\s*:?-+:?\s*)*\|?\s*$
  且必须同时包含至少一个 '-:' 或 ':-' 或 '-'（保证不是普通 `|`行）
  ```
- **表格内容行**：`^\s*\|.*\|`（只有处于 `IN_TABLE` 态才视为有效行）。
- **退出信号**：标题行 `^\s*#{1,6}\s`、空行、或非 `|` 开头的普通内容行。

### 2.3 状态转移

| 当前状态 | 触发条件 | 动作 | 下一状态 |
| --- | --- | --- | --- |
| NORMAL | 命中表格分隔行 | ①把**上一行**（非空表头）与分隔行包裹进来；②进入表格态 | IN_TABLE |
| NORMAL | 其它 | 原样写入正文行流 | NORMAL |
| IN_TABLE | 命中表格内容行 `|...|` | 累积到当前表格块 | IN_TABLE |
| IN_TABLE | 命中标题行 / 空行 / 非 `|` 内容 | ①关闭表格块；②作为**一个原子块**输出；③进入正文态 | NORMAL |
| IN_TABLE | 文档结束 | 关闭表格块并输出 | END |

### 2.4 输出约定
- 表格块作为**一个不可分割的整体**交给下游（图1 不打开、长度兜底不切），满足"表格保整"约束。
- 若某表格超长，仍整体保存（信息完整优先于长度均匀）；可在 metadata `type=table` 标记。

## 三、图2 —— 曲调行过滤状态机（`clean` 的第 2 步）

### 3.1 字符级判定
对正文行流中的每一行，逐字符扫描，只有当**整行全部字符**都属于允许集时才视为"曲调行"：

```
MELODY_CHARS = 数字0-9、点'.'、横线'-'、竖线'|'、空格' '、Tab
正则          ^[0-9.\-|\s]*$    （须整行非空）
```

### 3.2 状态转移

| 状态 | 事件 | 动作 |
| --- | --- | --- |
| 扫描 | 当前字符属于 MELODY_CHARS | 继续扫描 |
| 扫描 | 当前字符为其它（汉字、`,`、`(`、字母等） | 立即判定为「文本行」
| 行尾 | 全部字符均属于 MELODY_CHARS | **丢弃该行（不累积）** |
| 行尾 | 出现过任一非法字符 | **保留**，写入正文行流 |

### 3.3 防误判要点
- `1=F(或G)` 含 `F`、`G`、`(`、`)` → 保留 ✓
- `★` 分隔符非 MELODY_CHARS → 保留 ✓（由上层过滤）
- 曲调行样例 `5. 5  5. 5  5.  | 3  | 1  3  | 2  -` → 全为数字/点/竖线/空格 → **丢弃** ✓

## 四、图1 —— 标题层级状态机（`chunk` 主干）

### 4.1 标题识别与层级
```java
// 匹配 Markdown 标题；level = 连续 '#' 个数
Pattern HEADING = Pattern.compile("^\\s*(#{1,6})\\s+");
```
- `#` → level 1（一级标题，文档根章节）
- `##` → level 2（二级标题，子主题）
- `###`+ → level ≥ 3（小标题，**不单独成块**）

### 4.2 状态与缓冲区
- **累积态**：`List<String> buffer` 顺序追加当前行；记录本块所属标题路径（headingPath）。
- **flush 动作**：把 `buffer` 拼成文本产出为 1 个候选块 → 交给"超长兜底"拆分；随后清空 `buffer`，把**触发切块的那个标题行本身**写入新块，成为新块首行。

### 4.3 触发切块的判定规则（对照图1）

| 当前行 | 判定 | 是否触发 flush 新块 |
| --- | --- | --- |
| 一级标题 `#` | 文档根章节 / 大章节 | ✅ 必定新块 |
| 二级标题 `##` | 子主题切换 | ✅ 必定新块 |
| 三级及以上 `###`+ | 仍在当前大块内的小标题 | ❌ 累积，不切 |
| 连续内容行 | — | ❌ 累积 |
| 文档结束 | — | ✅ 强制 flush（收尾） |
| 原子表格块（来自图3） | 表格整体 | 作为一个独立块，不拆 |

> 说明：同一 `#` 顶级标题下，遇第一个 `##` 即子块刷新；`###` 永远不打断 `##` 大块——与图1 "这是个小标题，还在同一个大块中" 完全一致。

### 4.4 超长块兜底（防 embedding token 超限）
若一个语义块（含表格块）字符数 > `rag.chunk.max-chars`（默认 500）：
1. **优先按段落折行（`\n\n`）切分**，保持段落完整；
2. 若单段仍超长，再按句号 `。`/换行切；
3. 每个子块**保留本块所属的标题前缀**（如 `# 一、本科新生入学须知`），保证检索时能定位到章节；
4. 子块之间按需保留 `rag.chunk.overlap-chars`（默认 120）轻量重叠以承接上下文。

## 五、`jmu新生手册.txt` 分块推演（验收样例）

按上述流水线，目标文档预期的语义块划分（行号以源文件为准）：

| 块 | 内容范围 | heading 路径 | 类型 | 说明 |
| --- | --- | --- | --- | --- |
| 1 | L1–8 | 集美大学2025级新生入学须知完整文本 | text | 顶级 `#` + 学校简介元信息 |
| 2 | L9–22 | 集美学校校歌 | text | 曲调行(图2)被滤除后仅剩歌词/说明 |
| 3 | L23–33 | 校徽说明 / 校长致辞… | text | 逐 `##` 刷新 |
| … | … | 各 `# 一/二/三…` 章节 | text | `#` 大章节；内部 `###` 不打断 |
| N | L104–110 | 收费标准一览表（本科） | **table** | 图3 原子表格块，整体保存 |

关键验收断言：
1. **不再出现半句截断**：`当事人将承担相关法律…`（L85 结尾）与后续内容不再被 500 字硬切开。
2. **校歌块无简谱噪声**：`5. 5  5. 5 5. | 3...` 行全部消失。
3. **表格完整**：`收费标准一览表` 表头+分隔行+全部数据作为一个块。
4. **标题可定位**：每个块都带 `heading`、`level` 元数据，检索命中可回显章节。

## 六、配置项（新增，均可选）

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| `rag.chunk.max-chars` | `500` | 语义块上限，超限走段落兜底 |
| `rag.chunk.overlap-chars` | `120` | 超长兜底时子块间重叠 |
| `rag.chunk.enable-melody-filter` | `true` | 图2 曲调行过滤开关 |
| `rag.chunk.enable-table-preserve` | `true` | 图3 表格保整开关 |
| `rag.chunk.enable-heading-chunk` | `true` | 图1 标题切块开关（关闭则退回固定长度） |

`importDocument` / `rebuild(filePath)` 调用链保持兼容，仅内部 `chunk()` 替换为新流水线；**已入库的旧向量需经 `rebuild` 重新导入**才生效。
